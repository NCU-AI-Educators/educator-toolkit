# V11 学术语态审查标准 (Tone & Syntax Rules)

**用途**：在 `content_review_loop`（文风净化迭代阶段）被调用，作为强制扫描规则集。

> [!IMPORTANT]
> **适用范围**：本规则同时适用于 **SSOT 教材正文** 以及 `.master.md` 的全部五层结构（**幻灯片正文**、**逐字稿**、**双人对白**、**自学解释**、**教学设计**）。
> 幻灯片正文是投影在大屏幕上的静态文字，需要比逐字稿更精炼、更克制；双人对白与逐字稿需要自然平实的口语节奏，严禁演变成情绪化捧哏。

## 核心原则

**所有规则服务于一个目标：让文字读起来像是一个真实的人写的，而不是一台机器生成的。**

大语言模型有一种根深蒂固的生成倾向：把简单的事情用抽象名词包装起来，再用长定语串成一句话。这种文字语法上没错，但读起来不像人话。本规则集的首要任务就是识别并消灭这种倾向。


---

## 一、 句法结构法则（最高优先级）

> **如果一段文字只能靠眼睛反复阅读才能理解，而不能一遍听懂，那它就不合格。**

### 1. 短句优先
- 一句话只说一件事。超过 50 个中文字还没有句号的句子，必须拆分。
- 先说结论，再说原因。不要让读者/听众等半天才知道这段话的重点。

### 2. 禁止名词堆砌
AI 最常见的毛病是把多个名词或名词短语串在一起，形成一个没有动词、无法朗读的怪物。

| ❌ 名词堆砌（AI 典型产出） | ✅ 拆开说（人话） |
| :--- | :--- |
| 针对海量底层数据的标准探索与清洗方案 | 如何对大量原始数据做探索和清洗 |
| 基于客观扫描结果给出主观学术决断 | 拿到扫描结果后，由研究者自己判断 |
| 进而延伸到底层群体的另一面表征 | 再来看底层用户的情况 |
| 代码体力流丢给执行元件 | 把写代码的工作交给 AI |
| 链式规约为脏数据和逻辑盲区执行剥离切割 | 通过代码把脏数据一步步删掉 |
| 全样本排开雷达进行断层面体检 | 对全量数据做一次系统性的检查 |

### 3. 禁止隐喻轰炸
一段话里最多出现一个比喻。如果每个技术步骤都被包装成一个隐喻（真空舱、雷达、手术刀、排雷……），读者会迷失在比喻里，反而忘了你在讲什么。

### 4. 保护逻辑连接
精简文字时，必须保留"因此"、"然而"、"这说明"等连接词。句子之间要有因果链，不能变成一堆孤立陈述的堆砌。

## 二、 禁用词汇与表达

### A. 浮夸互联网黑话
| ❌ 严禁 | ✅ 替换为 |
| :--- | :--- |
| 神级、封神、顶级、王牌 | 经典、成熟、业界标准 |
| 灾难级、致命、毁灭性 | 严重缺陷、导致系统失效 |
| 绞肉机、命门、死结 | 瓶颈、关键制约因素 |
| 终极、总攻 | 最终/系统级、核心攻坚 |
| 完美、黄金 | 适配/最佳、标准/关键 |
| 满血 | 完整/无损、全量/完全 |

### B. AI 生造的伪学术词
大模型在字数压力下会把基础词汇强行拼成不存在的术语。**判断标准：如果这个词在任何正规教材或论文中都查不到，就是生造词。**

| ❌ 严禁 | ✅ 还原为 |
| :--- | :--- |
| 逆向倒灌、吞空主控 | 向上游蔓延并耗尽资源 |
| 深海账目、底座核域 | 核心数据模型、底层模块 |
| 斩截脱耦、突穿通路 | 消除依赖、跨越隔离层 |
| 代码体力流、脑容量留存 | 编码工作、把精力集中在 |
| 研究基座、认知跨越 | 研究基础、思维转变 |

### C. 情绪化修辞
| ❌ 严禁 | ✅ 替换为 |
| :--- | :--- |
| 极其要命的陷阱 | 容易被忽略的风险 |
| 疯狂浪费、极速拉满 | 消耗大量资源、显著提升 |
| 惨不忍睹、千疮百孔 | 存在较多问题 |
| 指数爆发、疯狂剧增 | 显著增长、复杂度上升 |
| 绝对 | 显著/明确/确定、(应避免主观臆断词汇) |

### D. 非正式开发口语
| ❌ 严禁 | ✅ 替换为 |
| :--- | :--- |
| 算费、查库、调包 | 费用核算、数据库查询、模块调用 |
| 跑批、塞库、洗数据 | 批处理、数据注入、数据清洗 |
| 底池、底盘、底座 | 原始样本集、基础架构、基础模块 |

### E. 综艺风转场
| ❌ 严禁 | ✅ 替换为 |
| :--- | :--- |
| 即将迎来、华丽现身 | 下一议题是、接下来讨论 |
| 带你揭开...的面纱 | 深入分析...的原理 |
| 准备迎接挑战了吗 | （直接删除，不需要这种煽动） |

### F. 说教口吻与第二人称
| ❌ 严禁 | ✅ 替换为 |
| :--- | :--- |
| 你们记住、你要知道 | （直接陈述事实，不用训导语气） |
| 帮你拦截、帮你做到 | 辅助完成、协助研究者 |
| 你必须、你需要 | （直接陈述要求，省略主语） |
| 傻傻地去、头脑一热 | 在缺乏评估的情况下 |
| 小白痛点 | 初学者常遇到的问题 |

> **幻灯片正文中"你"的特殊处理**：在案例设计中用"你"建立角色扮演情境是允许的（如"想象你是一名研究员"）。但标题、提示框和一般性描述中，禁止使用"你/你的"。

### G. 自媒体黑话（公众号标题党用语）
| ❌ 严禁 | ✅ 替换为 |
| :--- | :--- |
| 硬核 | 严谨、系统性 |
| 深水区、练兵场、军演 | 实战阶段、实践环节 |
| 试金石、沙盘 | 实践场景 |
| 快车道、入场券 | 高效的路径、第一步 |
| 破局、降维打击 | 解决方案、显著优势 |
| 赋权、跃迁 | 使...成为可能、提升/跨越 |
| 主权 | 自主权/自主性/控制权、(非地缘政治/数据隐私合规领域严禁滥用) |
| 物理 | 底层/实际/直接、(仅物理学科或确指物理硬件时合法) |

### H. 虚夸学术/科学修饰（严防滥用，但不封杀学科名词）
**判断原则**：当“学术”和“科学”作为标准学科名称或研究术语时（如“数据科学”、“科学假说”、“学术规范”）是合法且必须的；但严禁作为虚夸的形容词/副词来包装常规实验工作。

| ❌ 严禁滥用（浮夸风修饰） | ✅ 替换为（客观严谨语态） |
| :--- | :--- |
| 极具学术说服力、极具科学性 | 获得清晰明确的实测增益、数据说服力 |
| 学术归因、科学归因 | 实验归因、机制剖析、成因分析 |
| 科学剖析、科学洞察 | 深度剖析、机制分析、客观洞察 |
| 科学构想、科学解码 | 联合寻优构想、架构设计、深度解析 |
| 学术分析、学术现象 | 实验分析、客观现象、实验现象 |
| 核心学术贡献 | 核心作用、核心机制 |
| 正交拆解、正交方向、正交视角（滥用） | 各司其职、相互独立、递进维度（仅在严格数学/线性无关或完全解耦的二维坐标分类时方可使用“正交”，严禁将因果递进链条或普通分工包装为“正交”） |
| 三方模型、二元模型（过度简化缩写） | “人类主理—AI 编码—机器执行”三元协同机制（核心机制命名必须具备语义自明性，显式标出主体与权责动作，严禁简化为空洞的“X方模型”） |

### I. 对白与教学设计中的迎合赞叹与戏剧化口癖（严禁出现）
在 `类型: 对白` 与 `类型: 教学设计` 注释块中，严禁通过情绪化拟声词、吹捧赞叹或套路表扬来制造虚假的互动感：

| ❌ 严禁（戏剧化口癖与自夸套话） | ✅ 替换为（平实专业的工程师/师生交流） |
| :--- | :--- |
| 哈哈、哇！、天哪、哎呀、噢！、对对对 | （直接删除拟声起手词，直接陈述具体代码情境或疑问） |
| 太扎心了、太形象了、太透彻了、太真实了、太巧妙了、太清爽了、太酷了 | （删除吹捧感叹，直接用具体实验现象或边界条件接话） |
| 一针见血、醍醐灌顶、豁然开朗、比喻得特别到位 | （删除恭维套话，直接总结技术要点或追问下一步边界） |
| 完全正确、非常准确、一点不错、问到点子上了、抓到了核心、满分通关 | （删除居高临下的课堂评判前缀，直接给出机制拆解或事实结论） |
| 极具课堂互动效果、极具视觉冲击力、巧妙呼应、完美闭环、实战眼力 | （删除教案自夸评价，改为具体的课堂提问与验证动作） |
| 句末连续感叹号 `！`（单页对白出现 3~6 个 `！`） | 以句号 `。` 和问号 `？` 为主，单页对白 `！` 总数严格控制在 $0\sim 1$ 个 |

## 三、 语态基调

- **写作身份**：一位经验丰富的大学教授。讲话朴素、判断准确、从不卖弄。
- **核心追求**：清晰，而非华丽。每句话都有明确的信息增量，没有一个字是为了"听起来厉害"而存在的。
- **最终检验**：把写出来的文字念一遍。如果自己都觉得别扭，就重写。
